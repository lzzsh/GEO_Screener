# v2 验证记录 — 2026-09-10

## 交付版本与运行方式

开发分支为 `codex/v2-protocol`。原版 `main` 保留在 `ccc34f6`，并有标签 `v1-baseline-20260910`。本地 v2 通过 `python scripts/run_v2.py` 启动，入口为 http://127.0.0.1:8002/protocols，使用原有账号登录。

v2 的数据库、PDF、上传材料、提示词和会话签名密钥位于被 Git 忽略的 `data/v2/`。本地旧筛选任务和 Protocol 任务均在 v2 进程内执行，避免误投递到 v1 的 Celery worker。Docker 配置使用独立 Redis 和数据卷；本次验证了 Compose 配置解析，未进行容器构建或部署验证。

## Pi API 配置和真实调用

按用户要求读取 Pi 当前配置，使用 HPC provider 的 `https://hpc-api.westlake.edu.cn/v1` 和 `deepseek_pro` 模型。密钥复制到 v2 的用户模型配置，未写入源码或本文。原版数据库的模型配置没有修改。

该端点通过当前系统代理连接失败，直接连接可用。本地 v2 的私有 `runtime.json` 为该主机设置代理绕过，仍启用 TLS 证书校验。DeepSeek 推理响应较慢，提取器改为读取流式正文，并显式处理超时和输出截断。

通过真实 DeepSeek API 对一页、明确标记为合成调试样本的 PDF 提取成功：两条事件分别为 CHIR99021 3 uM、D0–D3，以及仅基础培养基、D3–D6。两条事件的来源页和引文均通过文本核验。初始返回的 `small molecule` 被枚举校验拦截，因此增加了明确的枚举提示和已知空格别名归一化。人工复核还修正了第二阶段的序号。

这证明了实际 API 和工作流可运行，不代表真实论文的生物学准确率已经验证。

## 浏览器与导出

在独立测试库中实际操作了以下流程：筛选详情选择文献 → 创建 Protocol 任务 → 上传 PDF → 开始提取 → 查看原文 → 编辑字段 → 标记已复核 → 下载已复核 TSV。

机器版本和人工版本均保留，当前版本为人工已复核版本。下载响应复查确认 **2 行、24 列**，扰动类型和阶段顺序与人工修订一致；证据 JSON 导出返回 HTTP 200。测试材料和导出保留在被 Git 忽略的 `output/playwright/v2-validation/`：

- `methods.pdf`：合成测试来源，不能作为研究证据。
- `reviewed.tsv`：人工复核后的 24 列结果。
- `reviewed-evidence.json`：对应版本、页码、引用和溯源信息。

另外解析了现有 `pdfs/GSE205224.pdf`：68 页、151,624 个文本字符，并渲染检查了第 45 页。该检查验证 PDF 解析和页码对应，不属于协议提取准确率测试。内嵌 PDF 的显示依赖浏览器 PDF 支持，页面同时提供原文件链接和逐页文本。

## 自动验证

针对性测试 **38 passed**，覆盖文献选择、材料校验、页码证据、时间和 GSM 校验、归属权限、复核导出、修订冲突、机器重跑保留人工版本、重复投递、过期任务重试，以及本地数据库/任务/提示词隔离。

JavaScript 语法和 Git diff 空白检查通过；另通过 Node 检查轮询恢复会清除网络错误、保留业务校验提示，并且返回中的请求不会覆盖刚输入的未保存修改。

完整旧测试集并未全部通过。保留原版的独立基线为 **43 passed / 5 failed / 21 errors**；最终 v2 为 **64 passed / 5 failed / 21 errors**。失败/错误测试名称与基线一致，主要涉及已删除的旧筛选 API 和测试数据库 fixture 隔离。没有改写这些历史测试来声称全量回归通过。

原版和 v2 副本的核心数据数量已逐项相等核验：1 个用户、11 个筛选任务、1,723 条筛选记录、8,868 个 GEO 样本、11,530 条 GEO 标签、121,061 条 GSM 标签、3 个文献库、108 条文献库记录。合成调试任务存放于独立测试库，没有混入用户的 v2 文献数据。
